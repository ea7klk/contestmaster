# Supported log formats

## Import

The application accepts UTF-8 Cabrillo 2.0 and 3.0 logs (`.log`, `.cbr`, `.cabrillo`, `.txt`) and text ADI/ADIF logs (`.adi`, `.adif`). ADIF is required by some digital contests and accepted as an alternative to Cabrillo by others. Each contest ruleset declares the accepted formats; the upload page displays that list and the API rejects formats not enabled by the selected contest. The importer supports ADIF's length-delimited text records, optional header ending in `<EOH>`, QSO records ending in `<EOR>`, and optional `<EOF>`. ADI/ADIF text is supported; ADX XML is not. See the [ADIF v3.1.8 specification](https://www.adif.org/318/ADIF_318_annotated.htm).

ADIF records use UTC `QSO_DATE` and `TIME_ON`, `CALL`, `MODE` or preferred `SUBMODE`, and `BAND` or `FREQ`. `BAND` values are normalized to catalog keys such as `2m`; a known band can also be derived from `FREQ`. Standard `STATION_CALLSIGN`/`OPERATOR`, `MY_GRIDSQUARE`/`GRIDSQUARE`, `RST_SENT`/`RST_RCVD`, `STX`/`SRX`, and `STX_STRING`/`SRX_STRING` are mapped where present. Configured contest exchanges still determine what is required and credited. The complete source file and unrecognized ADIF fields are retained for review. Unknown contest-specific extension fields are not automatically interpreted as scoring inputs.

Both importers are bounded to 5 MiB per file and the multipart request limit is 5 MiB plus 64 KiB overhead. Parsing is bounded at 100,000 lines, 8,192 characters per line, and 50,000 QSO records. A malformed file is rejected as a whole with source-line errors; no partial entry is created. Cabrillo versioned logs must start with `START-OF-LOG: 2.0` or `START-OF-LOG: 3.0` and end with `END-OF-LOG:`. A declared version other than 2.0 or 3.0, or a missing version after the colon, is rejected with a line-scoped error. The parser also accepts the older unversioned `START-OF-LOG` / `END-OF-LOG` markers as a compatibility extension; this does not mean that unversioned files conform to either specification. WWROF now marks v2 deprecated and recommends v3; v3 is intended to be backward compatible with v2 ([Cabrillo overview](https://wwrof.org/cabrillo/), [v3 header specification](https://wwrof.org/cabrillo/cabrillo-v3-header/), [QSO data specification](https://wwrof.org/cabrillo/cabrillo-qso-data/)).

This is version-aware Cabrillo support for the common header and QSO structure, not complete conformance to every sponsor-specific extension or template. A Cabrillo ruleset must explicitly configure each of the ten required QSO fields exactly once. WWROF documents that major contest sponsors accept those fields in different column orders, so the ruleset's selected contest template determines their order; validation does not require one universal order. The optional transmitter ID is supported as the final configured field. Validation rejects an omitted or incomplete template. Other trailing QSO fields are preserved for review. V3 `CATEGORY-*` headers can be mapped using configured category mappings. Every required category dimension must be reachable through each enabled log format's category mappings. The legacy v2 combined `CATEGORY` header is retained as an unknown header for review and is not automatically split into dimensions. The source text is retained exactly for later review or download. Existing immutable ruleset versions remain readable when they predate these authoring checks, but the API rejects such combinations in new drafts and saves.

Contest-specific exchanges are mapped using the configured exchange schema. Cabrillo requires exactly one `CALLSIGN` and `CONTEST` header, a matching contest name or slug, and at least one complete QSO. ADIF does not require a contest header; it identifies the station through `STATION_CALLSIGN` or `OPERATOR` when present and otherwise uses the station call carried by QSO records. ADIF QSO records require valid UTC date/time, callsign, band or supported frequency, mode, and exchange data. Cabrillo extensions, unknown headers, and ADIF QSO fields are retained as source metadata; generated exports are not guaranteed to round-trip byte-for-byte. Unsupported records, malformed UTF-8, ambiguous Cabrillo exchange token counts, and values that violate contest rules are reported for correction or review.

Acceptance of a Cabrillo or ADI/ADIF file does not mean the entrant's claims are adjudicated or credited. Ruleset validation, cross-log checking, duplicate selection, manual review, and publication policy are separate steps.

## Export

The public standings export currently supports deterministic `results-v1` JSON and CSV. An authorized entrant can download the exact stored original Cabrillo or ADI/ADIF revision through a receipt token or a verified participant session. Generating contest-specific Cabrillo result files and additional sponsor formats is not currently supported.

Ruleset format mapping enables the implemented Cabrillo and ADI/ADIF importers for a contest. CSV and native formats remain configuration labels only; they do not enable upload parsing.
