# N1MM profiles blocked from faithful conversion

**Scope:** N1MM Logger+ update 1.0.11466; static handler inventory compared with the current Contestmaster ruleset engine.

This is a complete list of factory dispatch keys for which this directory does not yet contain a fidelity-reviewed, importable Contestmaster ruleset. `blocked_from_import` means the conversion is incomplete, not that a profile is permanently impossible to express. Each row links to a structured record with the handler's source method locations and applicable capability gaps. Do not import these records as contest rules.

N1MM handlers are executable C#; Contestmaster accepts validated declarative configuration and never loads or executes these handlers. The shared engine currently has fixed, lookup, conditional, and Maidenhead distance points; per-rule multiplier counts and scopes; integer formulas over individual multiplier totals; declarative conditions; duplicate scopes; bonuses; and explicit Cabrillo/ADIF mappings. Thus older generic gap reports about all distance scoring or all independent multiplier arithmetic are stale. The remaining issue is exact per-profile translation and any handler behavior outside those supported facts, not absence of every general scoring primitive.

## How to read the blockers

- `profile_translation_unverified` is present for every record until its complete rule behavior has been translated and validated. A source method reference is a trace pointer, not an extracted rule.
- Specialized handler methods add a precise blocker family: points, final formula, multiplier source, duplicate identity, workability, exchange validation, sent/received exchange, Cabrillo layout, or incomplete default exchange metadata.
- The same handler can serve several keys and branch on the active key. A shared class does not make those profiles interchangeable; trace source references with the token branch in view.
- Before marking a key converted, obtain a target sponsor rule edition when applicable, map all scoring inputs to current typed rules, validate the JSON, and add expected-outcome tests. Keep event dates on Contestmaster contest records, not reusable rulesets.
- These records do not infer current status from N1MM's dispatch switch. Aliases, legacy keys, and discontinued entries need independent status verification.

See [the extraction README](README.md), [N1MM binary behavior notes](../../ruleset-parity/n1mm-functional-parity-plan.md), and tracking issue [#404](https://github.com/ea7klk/contestmaster/issues/404).
