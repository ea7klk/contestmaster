# N1MM Parity Behavior Matrix

This is the sponsor-verified benchmark for parity work tracked under [issue #385](https://github.com/ea7klk/contestmaster/issues/385). It converts the supplied N1MM 1.0.11466 executable comparison into portable rule outcomes. N1MM handler code is evidence of behavior to investigate; the linked sponsor edition rules are the authority. Examples are paraphrased and use no copied multiplier tables.

## Verified cases

| G1 distance scoring | [RSGB VHF/UHF/SHF General Rules 2026](https://www.rsgbcc.org/vhf/rules/26rules/General.shtml), together with a contest-specific rule such as [RSGB MGM special rules 2026](https://www.rsgbcc.org/cgi-bin/special.pl?rule=MGM&year=2026) | The general rules award one integer point per commenced kilometre; identical six-character locator squares score one point. | G2 entrant-relative geography | [CQ WW DX Contest rules 2026](https://www.cqww.com/rules/) | QSO points depend on the relationship between entrant and worked-station locations: different continents, same continent/different country, and same country have distinct point treatment. The same-country contact can still earn multiplier credit. North America has a defined point exception. | Given known entrant/worked entity and continent values, check each geography branch including the North America exception; verify same-country contacts receive zero QSO points but remain eligible for configured zone/country multipliers. Missing lookup remains null. Full cross-location branch fixture and portable-location override policy are not yet implemented. |
| G3 independent multiplier totals | [CQ WW DX Contest rules 2026](https://www.cqww.com/rules/) | The published final formula multiplies QSO points by the sum of zone and country multipliers. The two types are counted independently, once per band, and then combined by addition. | Use the published example: 1,000 QSO points, 30 zone multipliers, 70 country multipliers => `(30 + 70) * 1000 = 100,000`. Include a case with different zone and country counts to prove each source rule contributes the correct count. | Partial | The engine now computes a separate count per configured multiplier rule and preserves the aggregate count. Formula variables use `multiplier.<rule-id>` and are validated against configured rule IDs. Independent counters, overlap, conditional zero, unknown references, and legacy aggregate behavior are being covered. |
| G4 compound/QSO Party scoring | [Arizona QSO Party rules 2026](https://www.azqp.org/rules) | QSO points differ by mode; county multipliers count per band and mode for outside entrants; a contact with K7A earns a one-time entry bonus; final score is QSO points times multipliers plus bonus. Mobile/expedition entries have separate county behavior. | For a non-Arizona entry, confirm one new county on two modes counts as two multiplier credits, repeated county QSOs on the same band/mode do not add another credit, and repeated contacts with K7A award the one-time 100-point bonus only once. Exercise CW and phone point values separately. | Partial | Entry-side role/geography, county received-exchange field, mode-dependent scopes, and a condition over the worked callsign plus an aggregate unique-count bonus. The current bonus model cannot award a per-entry bonus from a qualifying QSO fact. |
| G5 workability and entrant conditions | [Arizona QSO Party rules 2026](https://www.azqp.org/rules) | Arizona stations may work everyone; non-Arizona entrants score contacts with Arizona stations. Exchange meaning depends on whether a station is in Arizona: Arizona sends its county; outside stations send state/province or DX prefix. Repeats for mobiles/expeditions depend on county changes. | Test an Arizona entrant and an outside entrant against Arizona and non-Arizona worked stations. Verify the required direction-specific exchange and county-sensitive duplicate identity. Missing or unresolvable region must trigger configured review/rejection, not silently pass. | Partial | Entrant and worked-station region facts, conditional exchange schemas, exchange-backed duplicate keys, and validations that ensure each referenced fact is available in the accepted format. |
| G6 handler-specific behavior | No sponsor rule is inferred from N1MM code alone. Select a sponsor rule source for each behavior before treating it as parity work. | N1MM's built-in handlers are executable implementations, not portable rule definitions. Only behaviors that can be represented by validated declarative primitives in this matrix are in scope. | For every selected profile, keep an expected-outcome fixture and a written mapping from the sponsor rule to configured rule types. A behavior that requires arbitrary executable code remains explicitly unsupported and blocks a parity claim. | Unsupported by design | Do not load/decompile-and-run N1MM handlers or add arbitrary code, callbacks, or `eval`. New primitives require a concrete sponsor rule and boundary tests. |
| G7 exchange and upload format | [Arizona QSO Party rules 2026](https://www.azqp.org/rules), plus Contestmaster's currently supported Cabrillo/ADIF format contracts | The sponsor's exchange direction changes with station region; both sides' sent/received exchange values are required to validate and score the entry. This benchmark does not imply that Contestmaster supports every format accepted by other sponsors. | Provide a valid Cabrillo fixture for Arizona and outside roles, plus invalid fixtures with the wrong exchange field, missing county/state, or reversed direction. If an ADIF ruleset is enabled for a profile, separately prove its mappings supply the same required facts. | Partial | Preserve source values, direction, ordering, and external field mapping. Conditional exchange configuration must be checked through each supported parser, not only schema validation. |
| G8 scoring session/reset semantics | [RSGB VHF/UHF/SHF General Rules 2026](https://www.rsgbcc.org/vhf/rules/26rules/General.shtml) | Serial numbers restart on each band; in cumulative contests they restart for each activity period. Duplicate recognition also differs between an individual contest and a cumulative activity period. | Test a repeated station at a new band and at a new configured activity-period boundary. Serials reset only at the configured sponsor boundary, while QSOs within one session remain sequential and duplicate checks follow the published repeat period. | Partial | Session identity/boundaries separate from recurring contest schedule. Current serial scopes have no session, and duplicate/multiplier state is currently entry-wide or scoped only by contact facts. |

## Limits and decision rules

- CQ WW 2026 is the worked reference for location-relative points and independently defined zone/entity multiplier totals. Its rules provide the exact arithmetic and selected edge case above.
- The Arizona QSO Party case proves a concrete QSO Party pattern; it is not a universal QSO Party template. Each state/province party needs its own sponsor-verified profile.
- RSGB distance rules vary by contest. The general rule's commenced-kilometre method must not override a special rule's locator precision, square origin, same-square value, or bonus. Test the applicable special rule together with the general rule.
- The N1MM report contains additional code branches and 263 dispatch tokens. This matrix is deliberately a benchmark set, not a claim that these cases alone establish parity for all built-ins.
- All sponsor examples selected for this benchmark have a current 2026 edition in the cited sources. N1MM-only aliases and discontinued dispatch names are not implemented by this matrix; they require sponsor-rule verification before inclusion.
- Results must remain deterministic, explainable and integer-valued. Geographic master data must use the version pinned to the contest start; submitted contest exchanges remain the authority for contest-specific sections, counties, grids and identifiers.
